# Known Designs Repository Instructions

## Communication Style

**Response Length:** Maintain a MEDIUM level of conciseness - not too terse, not too verbose. Strike a fine balance between brevity and completeness.

- Provide enough context and explanation to be helpful without being overly detailed
- For design discussions, system architecture, or Q&A: give thorough answers with key points but avoid unnecessary elaboration
- For implementation tasks: be direct and focused
- If the user says "be concise," avoid being overly terse - keep the medium balance
- When explaining trade-offs or design decisions: cover the main points without exhaustive detail

## Repository Purpose

This repository is primarily for:
- Questions and answers about known system designs
- Recording design patterns, architectural decisions, and trade-offs
- Documenting system design knowledge and insights
- Capturing interview preparation materials and real-world design examples

## Working in This Repo

When working on design documentation:
- Focus on clear explanations of design concepts
- Structure answers with appropriate depth for system design discussions
- Help organize and document design knowledge effectively
- Use diagrams and examples where they add value
- Keep technical discussions practical and grounded in real-world considerations
